## Shipped source promise and acquisition

The mod registers six OC2R `BlockDeviceProvider`s for existing Create block entities (`src/main/kotlin/.../integration/oc2r/Oc2rCreateProviders.kt`, wired by `ComputerBridgeMod.kt`): rotation speed controller, creative motor, sequenced gearshift, sticker, speedometer and stressometer. It supplies RPC devices for speed control/reading, sequencing, sticker operation, stress reading, and speed/stress change events; it does **not** add a new block, recipe, item, GUI, or computer. See `api/devices/`, `compat/adapters/kinetics/`, `compat/events/` and `compat/providers/CreateBlockEntityDeviceProvider.kt` for actual method/attachment behavior. The provider only supplies a device when the queried position has a matching block entity. Diagnostics are optional and bounded (`diagnostics/`). The description in `gradle.properties` says Create's *documented CC: Tweaked peripheral API*; the implementation here is an OC2R object-device bridge, not a promise of native CC computers or a new CC GUI.

Acquisition references: the six Create blocks are `com.simibubi.create.AllBlocks` / Create's own items and recipes, **not** registrations in this repository; the existing GameTest uses `AllBlocks.STICKER`. Inspect the resolved Create 6.0.8 mod and the actual pack recipes/quest/JEI for survival availability, crafts, stress/power prerequisites and any pack overrides. OC2R computers, hardware, software and connection components come from the pinned OC2R 2.2.12 and pack configuration, not this mod. No local recipe-root or GUI acquisition test exists; do not infer accessibility from provider registration or from a creative-inventory/GameTest block placement. Creative motor availability must not be mistaken for ordinary survival acquisition.
